# Convert-PFX

Разбирает PFX на сертификат и закрытый ключ или собирает PFX из сертификата и ключа. Работает через `openssl`.

Направление выбирается по расширению входного файла:

| Вход | Результат |
|---|---|
| `.pfx`, `.p12` | `<имя>.crt` (сертификаты) и `<имя>.key` (ключ без пароля) |
| `.crt`, `.cer`, `.pem` | `<имя>.pfx` из сертификата и ключа `<имя>.key` (или `-KeyPath`) |

## Требования

- PowerShell 7.x (на Windows PowerShell 5.1 не проверялся).
- OpenSSL 3.x в `PATH`. Проверено с OpenSSL 3.4.0 (сборка OpenSSL-Win64).

## Примеры

```powershell
# Разобрать PFX: пароль будет запрошен скрыто
Convert-PFX .\site.pfx

# Разобрать, ключ в формате BEGIN RSA PRIVATE KEY, в .crt только сертификат сервера
Convert-PFX .\site.pfx -Traditional -LeafOnly

# Собрать PFX из site.crt и site.key, пароль будет запрошен дважды
Convert-PFX .\site.crt

# Собрать из fullchain.pem и privkey.pem (например, Let's Encrypt) с понятным именем
Convert-PFX .\fullchain.pem -KeyPath .\privkey.pem -FriendlyName 'site.ru 2026'

# Собрать PFX с промежуточным сертификатом для старого Windows Server
Convert-PFX .\site.crt -ChainPath .\intermediate.crt -Compat

# Разобрать все PFX в папке
Get-ChildItem *.pfx | Convert-PFX -Passwd (Read-Host -AsSecureString) -OutDir .\out
```

## Параметры

| Параметр | Режим | Описание |
|---|---|---|
| `PathPfx` (позиция 0) | оба | Входной файл. Принимает объекты из `Get-ChildItem` через конвейер |
| `Passwd` (позиция 1) | оба | Пароль PFX: `SecureString` или строка. Если не указан, запрашивается. Пустая строка — PFX без пароля |
| `OutDir` | оба | Папка для результата. По умолчанию — папка входного файла |
| `Force` | оба | Перезаписать существующие выходные файлы |
| `Traditional` | разбор | Ключ в старом формате (`BEGIN RSA PRIVATE KEY` / `BEGIN EC PRIVATE KEY`) вместо PKCS#8 |
| `LeafOnly` | разбор | В `.crt` только сертификат сервера, без цепочки |
| `KeyPath` | сборка | Путь к закрытому ключу. По умолчанию `<имя сертификата>.key` рядом с сертификатом |
| `KeyPasswd` | сборка | Пароль зашифрованного ключа, если он отличается от пароля PFX |
| `ChainPath` | сборка | Файл с промежуточными сертификатами для добавления в PFX |
| `FriendlyName` | сборка | Имя сертификата в PFX (видно в оснастке сертификатов Windows). По умолчанию — имя файла |
| `Compat` | сборка | Шифрование 3DES/SHA1 вместо AES-256/SHA256 — для Windows Server 2016 и старше, старых Java |

## Как работает

- **Пароль** передаётся в `openssl` через временную переменную окружения (`-passin env:...`), а не в командной строке. После работы переменная удаляется.
- **Старые PFX** (RC2-40) при разборе читаются с `-legacy` автоматически. Если `legacy.dll` лежит рядом с `openssl.exe` (так ставит OpenSSL-Win64), путь к нему подставляется на время вызова.
- **Перед сборкой** проверяется, что ключ подходит к сертификату. Сертификат в DER (`.cer` из Windows) переводится в PEM сам.
- **После сборки** PFX читается обратно для проверки.
- **При ошибке** (неверный пароль, неподходящий ключ, нет файла) частично созданные файлы удаляются, временные файлы не остаются.
- Функция возвращает объект с путями и числом сертификатов, его удобно передавать дальше по конвейеру.

> ⚠️ После разбора закрытый ключ лежит **без пароля**. Храните `.key` в защищённой папке и удаляйте, когда он больше не нужен.
